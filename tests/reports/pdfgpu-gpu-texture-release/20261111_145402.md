## 측정값이 세는 것 / 측정하지 못한 것

- `texturesCreated` / `texturesDestroyed`는 **가짜 device의 `createTexture`
  호출 수와 `texture.destroy()` 호출 수**다. 실제 GPU 할당량이 아니다.
  `liveTextures = created - destroyed`.
- `leakedTextures = liveTextures - cachedRastersAtEnd`. "캐시가 이미 버린
  raster의 텍스처"를 센다.
- **바이트는 측정하지 않았다.** `imageSize()`가 `ImageBitmap` /
  `HTMLCanvasElement` / `HTMLImageElement`만 인식하고 Node에는 셋 다 없어서
  가짜 source가 모두 1x1로 계산된다. 따라서 `gpuTextureBytes`는 이 환경에서
  의미 있는 값이 아니며 테스트도 그것을 주장하지 않는다. 실제 규모를 환산하면
  512x512 RGBA 타일 1장 = 1,048,576 bytes이므로, 위 측정의 누수 190장은
  약 199MB에 해당한다.
- **브라우저에서는 F2를 측정하지 못했다.** Playwright 컨테이너에 WebGPU가 없어
  모든 프레임이 `backend: unsupported`로 기록된다(`[PW CONSOLE] info [pdfgpu]
  render frame {... backend: unsupported ...}`). `renderWebGpu`가 실행되지
  않으므로 배포 검증은 2D fallback 경로의 무회귀만 보인다. WebGPU 경로의 실제
  GPU 메모리 추이는 WebGPU 지원 브라우저에서 따로 확인해야 한다.

## 반증된 가설

처음에는 `WeakMap`이 "해제가 느릴 뿐"이라고 볼 여지를 남겨 뒀다. 측정 결과
파괴 호출이 **0회**였고, 소스에서 원인도 확인됐다. `GpuTextureEntry`가 `source`
필드를 가지므로 엔트리를 담는 강한 `Set`이 WeakMap의 키까지 전부 붙잡는다.
약한 참조가 느리게 동작한 것이 아니라 아예 무효였다. GC를 기다려도 회수되지
않는다.

또 하나: `prune(keepKeys)`가 비보유 키를 버릴 것으로 기대했으나, `evict`는
`bytesUsed > maxBytes`일 때만 루프를 돌기 때문에 상한 이하에서는 아무것도
버리지 않는다. 이번 수정 범위는 아니며 F5로 남아 있다. 이 때문에 텍스처 해제도
상한에 닿기 전에는 일어나지 않는다 — 누수는 막혔지만 해제 시점은 캐시의
축출 정책에 묶여 있다.
